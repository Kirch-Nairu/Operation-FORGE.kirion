# Context Renewal Protocol

Long conversations accumulate obsolete hypotheses, rejected options, temporary failures, and irrelevant history. Forge deliberately renews context before that noise becomes an execution risk.

## Triggers

Consider context renewal when:

- the conversation is dominated by old execution detail;
- architecture decisions are already durable but exploratory discussion remains large;
- a new role is beginning;
- the current context risks confusing stale and current authority;
- an execution session has ended;
- the user is transferring work to another account or model.

## Procedure

1. stabilize current project state;
2. update durable project memory;
3. produce a continuity or role handoff;
4. identify exact repository authority;
5. start a fresh conversation;
6. bootstrap Forge;
7. load current project memory and handoff;
8. verify repository reality;
9. continue.

Context renewal is garbage collection, not loss of intelligence.
