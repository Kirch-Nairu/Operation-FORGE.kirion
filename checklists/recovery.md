# Recovery Checklist

- [ ] Incident/current failure state is preserved.
- [ ] Accepted authority and affected runtime state are identified separately.
- [ ] Recovery objective is explicit.
- [ ] Backup/quarantine refs exist where needed.
- [ ] Dirty/uncommitted work is preserved before destructive cleanup.
- [ ] Data implications are known.
- [ ] Recovery actions are authorized.
- [ ] Validation required to prove recovery is selected.
- [ ] Recovery provenance and remaining unknowns will be recorded.
