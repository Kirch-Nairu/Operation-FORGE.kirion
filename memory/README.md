# Forge Memory

## What is this?

The memory subsystem defines how project knowledge is created, kept current, compacted, superseded, archived, and reconstructed by a fresh agent.

## When do I load it?

Load the README and [continuity.md](continuity.md) when starting fresh. Load [reconciliation.md](reconciliation.md) when memory disagrees with Git, runtime, or a handoff. Load compaction/supersession material when maintaining durable records.

## What is canonical?

- [lifecycle.md](lifecycle.md) — record lifecycle.
- [reconciliation.md](reconciliation.md) — conflicts between memory and observed reality.
- [hot-warm-cold.md](hot-warm-cold.md) — progressive loading tiers.
- [compaction.md](compaction.md) — reducing historical context without losing provenance.
- [supersession.md](supersession.md) — how records stop being active authority.
- [continuity.md](continuity.md) — reconstructing state without old conversations.

The portable doctrine remains [doctrine/memory-model.md](../doctrine/memory-model.md).

## Dependencies

Memory depends on explicit [authority](../doctrine/authority-model.md), Git history, and observable runtime state. Memory cannot override them.
