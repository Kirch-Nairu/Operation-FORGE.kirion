# Project Intake Protocol

Use when Kirch proposes a new project, product, module, skin, or variant.

Do not implement yet.

## Intake flow

1. Identify product category.
2. Hypothesize the minimum viable version.
3. Identify first user and daily workflow.
4. Separate include, exclude, and parked scope.
5. Run cost-free dependency scan.
6. Map Salryn Standard parent reuse.
7. Ask structured questions.
8. Produce Project Constitution.
9. Ask for APPROVED / REVISE / PARK.

## Required output

- hypothesis
- MVP checklist
- parked checklist
- cost scan
- parent reuse map
- implementation surface map
- open questions
- approval gate

No code before approval.
