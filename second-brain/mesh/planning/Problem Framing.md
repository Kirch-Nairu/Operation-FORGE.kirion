# Problem Framing

Problem framing separates the observed pain from the proposed solution. It defines actors, current state, desired outcome, causal assumptions, evidence, and the cost of being wrong before architecture begins.

## Engineering use
A frame should be strong enough that two engineers can disagree about implementation while still agreeing on the problem.

## Failure questions
- Are we solving a symptom instead of the cause?
- Is the requested feature actually the desired outcome?
- Which observation would falsify the frame?
