# Scope Boundary

A scope boundary states what the current engineering commitment owns and what it explicitly does not own. It prevents adjacent requirements, future ideas, and implementation convenience from silently expanding delivery obligations.

## Engineering use
Scope should be traceable to outcomes, acceptance criteria, dependencies, and change-control triggers.

## Failure questions
- Which request would cross the approved boundary?
- Which dependency is required but not owned?
- What becomes a new phase rather than a hidden addition?
