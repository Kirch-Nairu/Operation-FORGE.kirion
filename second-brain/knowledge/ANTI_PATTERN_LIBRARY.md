# Anti-Pattern Library

Anti-patterns preserve recurring approaches that appear attractive but repeatedly create failure, ambiguity, cost, or unsafe authority.

## A useful anti-pattern records

- tempting approach
- why it looks reasonable
- failure mechanism
- evidence / incidents
- signals it is happening
- safer alternative
- contexts where the warning does not apply

Seed examples:
- UI as authorization
- chat memory as repo truth
- feature stacking inside active lane
- untested backup confidence
- temporary production code
- parallel sources of truth
- architecture-by-vendor
- adding distributed systems before a demonstrated need
