# V3 Native Graph Topology Contract

The V3 graph is deliberately large. Large does not mean indiscriminate.

## Shape rule

```text
Cognitive control plane
  -> macro engineering families
      -> semantic lanes / subdistricts
          -> domain system hubs
              -> dense local concept neighborhoods
                  -> real bridge corridors
                      -> adjacent families / project packets
```

Project packets attach implementation reality to the concepts and decisions they actually exercise. Macro families provide broad semantic zoning. Semantic lanes are intermediate navigation/gravity nodes that make a large family readable without becoming implementation authority. Bridge corridors represent actual engineering flows across zones.

## Lane rule

A semantic lane groups a small set of domain anchors that answer one recognizable engineering question, such as identity/access, data/state, build/release, or decision/evidence. Lanes must remain narrow enough to be legible and truthful.

A family should normally route through lanes instead of linking directly to every domain system hub. Lanes do not form decorative rings and do not universally link to sibling lanes. Cross-family movement remains the job of real bridge concepts and bridge corridors.

## Local density rule

Atomic concepts should normally have a parent/subhub and several same-domain relationships. Triangles and short local cycles are desirable when they represent real semantic reinforcement. The objective is to make each district visually legible as a dense constellation.

## Macro-family rule

A macro family groups districts that frequently reason together, such as product/planning/commercial/delivery or deployment/CI/CD/operations. A family is navigation and cognition, not a source of implementation truth.

## Bridge-corridor rule

Cross-domain edges are valuable when they express an actual engineering dependency: architecture/security/deployment, data/integrity/recovery, decision/evidence/risk, quality/testing/release, product/scope/commercial/delivery, incident/recovery/learning, AI/authority/verification.

A corridor is allowed to be cross-domain by design. Decorative cross-links are prohibited.

## Project packet rule

Projects are cognition integration tests. A project hub routes into focused packet views such as repository truth, scope, architecture, security, data, recovery, verification, deployment, commercial scope, decisions and incidents. The project root must not become a universal backlink target.

## Authority rule

Repository/runtime evidence remains authority for live implementation state. A cognition packet may preserve a verified snapshot but must declare that snapshot and require re-anchoring before consequential decisions.

## Prohibition

No fake graph edges, no static renderer, no coordinate forcing, no links added solely to draw a shape. Native Obsidian physics must emerge from real semantic structure.
